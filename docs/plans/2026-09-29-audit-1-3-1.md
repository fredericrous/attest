## Commits (in order; each passes `make check` on its own)

### 1. `fix: keep unpushed blocks in their own ref` — finding 3
The conflict: "keep local-only blocks" and "deleting on origin revokes" cannot
both hold on one ref, because a block's bytes don't say whether it was ever
pushed. So split by provenance:
- **`refs/notes/amont-attest[-inputs]` is origin's mirror**, owned by the
  verifier. Fetch succeeds → force-updated (as today). Origin reachable but
  the ref absent (see "Remote calls" for the one exit-code rule) → the local
  mirror is **deleted** (today it is kept:
  a deletion on origin never propagated); if that `update-ref -d` fails
  (read-only or locked `.git`), the mirror is not judged. Origin configured
  but the fetch fails for any other reason (unreachable, no credentials) →
  the mirror is **not judged**, and the log says why — a stale mirror on a
  persistent runner must not outlive a revocation. Only when there is no
  remote named `origin` at all (`git remote get-url origin` fails) is the
  local ref judged as-is; the conformance fixtures rely on that.
- **`refs/notes/attest-local/amont-attest[-inputs]`** holds blocks written
  with `--no-push`. `sign.sh` `publish_local` writes there; `publish` no
  longer calls `absorb_local` (deleted), so a push never re-publishes a
  revoked or local-only block. Origin cannot revoke these, so verifiers
  read them **only on request**: `--include-local` in `verify.sh` and
  git-attest, `include-local` input on `action.yml` (default false). A
  persistent runner's `push: false` blocks therefore never cover later jobs
  by default.
- Verifier visit order, identical in both implementations and written into
  SPEC "Lookup": per candidate (`HEAD^{tree}`, `HEAD`, `HEAD^2`, then the
  lazy fingerprint keys) the mirror, then `attest-local` when requested.
  Dedup and the 64-verification budget stay shared. `--include-local`
  blocks are read whether or not the mirror is judged.
- Mechanics. Rust: `fetch_notes` returns
  `enum Mirror { Fresh, NoOrigin, Deleted, Unusable(String) }` per ref;
  `evaluate` builds the list of refs to read (mirror only if `Fresh` or
  `NoOrigin`, plus `attest-local` if asked) and both candidate loops take it;
  the `rev-parse` "local copy exists" fallback (`attest.rs:224`) is deleted;
  `update-ref -d` failure → `Unusable`. Shell: `fetch_notes` sets a per-ref
  "judge the mirror" variable the loops consult; same outcomes.
- No prompts, no hangs: every `fetch`/`ls-remote` runs with
  `GIT_TERMINAL_PROMPT=0`, stdin null, and — unless `GIT_SSH_COMMAND` or
  `core.sshCommand` is set — `GIT_SSH_COMMAND='ssh -o BatchMode=yes -o
  ConnectTimeout=10'`, and `-c http.lowSpeedLimit=1 -c http.lowSpeedTime=10`
  so a stalled https origin (CI's case) is bounded too (`src/git.rs` gains a
  remote-call helper; `verify.sh` the same).
- Remote calls per run, both refs together: one `git fetch` with both
  refspecs. If it fails, one `git ls-remote --exit-code origin` naming both
  refs. The one rule: exit 0 → the listed refs exist, each unlisted one is
  absent (mirror deleted), then one more fetch of the refs that exist; exit 2
  → both absent, both mirrors deleted; any other exit → both unreachable,
  stop. Fixture: origin reachable with neither ref → `notes=absent
  inputs_notes=absent`, both mirrors deleted. A stalled origin therefore costs at most two
  calls × 10 s ≈ 20 s; a healthy one with no inputs ref costs three quick
  calls. The extra `ls-remote` round-trip happens only when the fetch
  fails, as today.
- What people see — one wording, byte-identical in both implementations,
  every line through `note()` / the Rust reason sink:
  - mirror deleted (printed even under `--quiet`, since it changes data):
    `attest: origin has no refs/notes/<ref>; deleted the local mirror (was <oid>); restore: git update-ref refs/notes/<ref> <oid>`
  - fetch failed with origin configured (replaces today's now-false "no
    local copy exists" line, `verify.sh:159`, `attest.rs:230`):
    `attest: cannot fetch refs/notes/<ref> from origin (no credentials? persist-credentials: false?); local mirror not judged, running everything`
  - `attest-local` has blocks but `--include-local` is off:
    `attest: refs/notes/attest-local/<ref> holds unpushed blocks, ignored without --include-local`
  - `--github-output` gains `notes=` (main ref) and `inputs_notes=` (inputs
    ref), each `fetched|absent|unreachable|no-origin`; `action.yml` emits `::warning::` on `unreachable` and exposes
    the output, so a fleet-wide fall to "covers nothing" is visible.
- Flag and input: `--include-local` in `verify.sh`'s usage block (fix the
  `sed -n` help range) and in git-attest (`parse` boolean arm, not the value
  arm; `USAGE`; unit test next to `an_unknown_flag_is_a_usage_error`).
  `action.yml` `include-local`: `true` → flag, `false`/empty → nothing,
  anything else → exit 2. `make lint`: `--help` of both mentions every flag
  the parser accepts.
- `sign.sh` `publish`: set the local main ref after a push only when
  `--remote` is `origin` (another remote's content must not enter the mirror).
- The CI `action` job changes land HERE, not in commit 6, so every commit
  passes CI: `origin` → empty bare repo in `$RUNNER_TEMP`, hand-signed notes
  pushed there, "appended locally" reads `attest-local`, strict/loose/os-only
  pass `include-local: true`, one step without it proves the block is ignored.
- Files: `verify.sh`, `src/attest.rs`, `src/git.rs`, `src/main.rs`,
  `sign/sign.sh`, `action.yml`, `.github/workflows/ci.yaml` (`action` job),
  `Makefile`, tests.
- Fixtures (`tests/sign.sh`, run against BOTH implementations via
  `ATTEST_BIN` from `Makefile sign-test`): `--no-push` block survives a verify,
  is covered with `--include-local` and not without; push a gate, delete the
  origin ref → signer clone and a fresh clone both cover nothing, and the
  signer's next push does not bring it back; a 1.3.1-style clone (local ref =
  old origin content) with origin deleted → `""`; origin set to an
  nonexistent `file://` URL with a populated mirror, stdin `</dev/null`, under
  a timeout → `""` plus the exact log line, and `diff` of both
  implementations' stderr empty; an `http://127.0.0.1:<port>` origin served by
  a listener that accepts and never replies (libcurl, the same path as
  https) → both return under `timeout 30` (2 calls × 10 s + slack) with
  `notes=unreachable` and `inputs_notes=unreachable`; the deleted-mirror line's restore command
  brings the ref back; a `tests/fault/git` mode `env` records that
  `fetch`/`ls-remote` saw `GIT_TERMINAL_PROMPT=0` and the BatchMode ssh
  command; mirror delete made to fail (`chmod` the refs dir, restored by a
  trap on `EXIT INT TERM`) — the fixture first proves its premise by failing
  `update-ref -d` on a scratch ref and prints a visible SKIP otherwise
  (Windows, root, reftable, packed refs) → `""`. Existing "local ref kept the local-only block" assertions
  move to `attest-local`. Conformance: a budget-exhausting fixture split across
  mirror and `attest-local`, run with `--include-local` (else half is unread).
  SPEC "Lookup": the no-origin case (local ref judged as-is) exists for
  fixtures and local use; CI must have `origin`.
- SPEC/README: what each ref is; unpushed blocks never leave the machine;
  `git update-ref -d refs/notes/attest-local/…` discards them. CHANGELOG: on
  upgrade the main ref becomes origin's mirror, so blocks that exist only
  there — a 1.3.1 `--no-push` block absorbed into it, or any note in a clone
  whose origin never had the ref (1.3.1 kept those, `verify.sh:157`) — are
  dropped by the first 1.4.0 verify; re-sign with `--no-push` to keep one.
  An origin that is configured but unreachable now covers nothing.

### 2. `fix(verify): literal gate names in fp lookup` — finding 7
Real defect: `awk -v g=…` processes backslash escapes, so `verify.sh` covers a
signed gate `te\163t` via spec gate `test`; git-attest does not.
- Every awk that compares against a caller value reads it from `ENVIRON`
  (POSIX; BSD awk, mawk, gawk), never `-v`: `input_fp`, `spec_paths`, `field`,
  sign.sh's `fingerprint`, `tests/lib.sh` `fp_of`.
- `kept_gates`: fingerprint-eligible only if, under `LC_ALL=C`, the first
  character is alphanumeric, no character is outside `A-Za-z0-9._-` (class
  spelled out), and `${#g} -le 64`. Keeps `$tmp/fp.$g` safe too.
- Fixtures (both impls): `te\163t` gate claiming `test`'s fingerprint → `""`;
  a 65-character gate → not fingerprint-covered.

### 3. `fix: platform names and empty flags match` — finding 6 + minor
- One table in `verify.sh`, `sign/sign.sh`, `tests/lib.sh` between
  `# platform-table:start/end` markers, emitting Rust `std::env::consts`
  names. Arch: `arm64|aarch64→aarch64`, `amd64|x86_64→x86_64`,
  `i386..i686→x86`, `armv*→arm`, `ppc64*→powerpc64`, `ppc→powerpc`, else raw;
  on SunOS the arch comes from `isainfo -k` (`amd64→x86_64`), since `uname -m`
  says `i86pc`. OS: `Darwin→macos`, `Linux→linux` (`android` when `uname -o`
  says Android), `MINGW*|MSYS*|CYGWIN*|Windows_NT→windows`,
  `SunOS→illumos|solaris` by `uname -o`, else lowercased `uname -s`. SPEC:
  a residual mismatch can only lose a skip.
- `make lint` + CI lint: the three marked tables must be byte-identical.
- `src/main.rs`: empty `--signers/--principal/--platform` means "not given",
  as in `verify.sh` and the actions — accepted by `parse`, mapped to `None`
  on assignment (not filtered from the value chain, which would exit 2; no
  `is_none_or`, MSRV 1.74). Rust unit test.
- Fixtures: `tests/fake/uname` (+ `isainfo`), pattern of `tests/fault/git`,
  shell impl only with visible SKIP: FreeBSD/amd64, Linux/armv7l,
  SunOS/i86pc, MINGW64. `tests/sign.sh`: the written `platform` line for the
  same. Conformance: each empty flag still covers. Add `tests/fake/*` to both

### 5. `feat(spec): optional paths bind their absence` — finding 1 (structural)
- Grammar: a path token may start with one `?`; the stripped rest obeys the
  existing rules, and both awks test it for empty explicitly (awk
  `split("")` returns 0 where Rust yields `[""]`). `??x`, `?`, `?/x` invalid.
  Strip before computing ancestor `.gitattributes`.
- `?p` is exempt from the must-resolve `cat-file --batch-check` check; it is
  listed stripped in `ls-tree`. Absent → no records; appears → fingerprint
  changes. `sign.sh` prints ONE summary line through `say()` (so `--quiet`
  hides it), unique paths only:
  `attest-sign: optional paths absent (their absence is bound): examples benches …`
  — short enough that a typo like `?biuld.rs` stands out.
- Code: both `load_spec` awks and `fp_head`/`fingerprint` (`verify.sh`,
  `sign.sh`); in `src/attest.rs` the spec stores
  `struct PathTok { path: String, optional: bool }`, so the stripped path is
  the only string `cat-file`, `implicit_inputs` and `ls-tree` can see; the
  `cat-file` input and its count check take required tokens only;
  `parse_spec`, `path_error`, `fingerprint`; `fp_of` in `tests/lib.sh`.
  Fixture: `g ?nope src` fingerprints equal to `g src`.
- Fixtures: absent → covered; added → nothing; present and changed →
  nothing; `docs ?` and `docs ?a/b` agree across impls; grammar errors
  invalidate; an all-optional gate works. One fixture builds the expected
  `ls-tree -z` bytes by hand (printf of mode/type/oid/path) so `fp_of` isn't
  checking itself. Rust grammar unit tests.
- Compat: freeze `tests/compat/verify-1.3.1.sh` from `v1.3.1`; `build_tag
  v1.3.1`; `compat-fields.sh` mode `fp13` + a case: `?` spec, block only under
  its key → old/fp13 `""`, new covered.
- SPEC/README: the marker; 1.3.x readers and amont's producer reject `?` as a
  wildcard (`verify.sh:330` at 1.3.1, amont `attest.rs:212`), so a spec using
  it only loses fingerprint skips there. amont support is a follow-up in its
  own repo. Rewrite the `.github/attest-inputs` header comment.
